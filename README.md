# KisanSetu AI — IIITD HackShift prototype

A React + TypeScript + Vite + TanStack Router prototype for an Indian agriculture platform. This version adds a sign-in portal, a demo-session gate, a sign-out control, image fallbacks, and distinct role-specific overview workspaces. It retains the interactive crop-health upload, rule-based bilingual advisory, mandi trend graph and proceeds calculator, irrigation planner, marketplace listings and offers, machinery booking demo, residue exchange, community, and official scheme links.

## Run locally

Requirements: Node.js 20+ (Node 22 recommended) and npm.

```bash
npm install
npm run dev
```

Open the local URL Vite prints, usually `http://localhost:5173`.

Production build:

```bash
npm run build
npm run preview
```

## Demo access

Open the app and use **Continue as demo farmer**. The email/password fields are a local prototype portal and accept the entered values; they do not create or validate a real account. Session state is stored in browser local storage. Use the role selector in the sidebar to preview Farmer, Buyer / FPO, Machinery Owner, Agricultural Expert, and Administrator workspaces. The role selector is only a UI demo and is not production authorization.

## Important demo limitations

- Mandi prices, MSP references, weather values, distances, listings, and activity indicators are illustrative sample data, not live feeds.
- Crop Doctor previews an uploaded image and shows a guided demo assessment; no plant-disease model is connected.
- Kisan AI responses are rule-based examples, not generated by a live AI service.
- Listings, offers, community posts, and bookings are local in-memory demo interactions and do not sync to other users or persist in a database.
- A Supabase integration scaffold is present in the project, but this prototype's demo sign-in does not authenticate against Supabase.
- The separate `/auth`, `/reset-password`, and `/dashboard` routes require `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Without them, authentication actions are disabled and protected dashboard access returns to the setup notice; no backend success is simulated.
- Images use remote Unsplash sources when available and fall back to a local SVG-style agricultural illustration if an image fails to load.

Before production use, connect a real authentication provider, backend persistence, role-based authorization, verified market/weather data sources, and a secure vision/LLM service. Never use demo values to make real agricultural, medical, or financial decisions.

## UI refresh notes

The latest UI pass replaces the tall scrolling sidebar with a compact, fixed-height navigation rail that keeps all 10 tools visible on typical laptop displays. It adds active-state icon tiles, a compact role switcher, a dedicated Kisan AI shortcut, stronger visual hierarchy, hover/entrance transitions, and a brighter layered farm-insight hero. The app remains a demo prototype: visual polish does not turn illustrative market, weather, AI, or role data into live/production data.


## Prototype account and data notes

- The sign-up/login flow in this prototype stores demo accounts in the current browser's `localStorage`. It is for a hackathon demonstration only, **not secure production authentication**. Do not use real passwords or sensitive personal information.
- “Forgot password” explains the current limitation. Configure Supabase Auth email recovery before claiming password-reset emails are sent.
- Market prices, listings, and forecast statements shown in sample screens are illustrative unless a live provider, source, and timestamp are explicitly shown. Do not present demo figures as current market data.
- To configure your own Supabase project, copy `.env.example` to `.env.local` and fill in the appropriate values. Never commit secrets.
- Regional language selector includes English, Hindi, Punjabi, Marathi, Bengali, and Tamil labels; this prototype still needs full translation coverage and verified language-specific AI/voice behaviour before production.
